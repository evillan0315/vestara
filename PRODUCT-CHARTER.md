# The Vestara Product Charter

> **The Architecture Era answered how Vestara should be built.**
> **The Product Era answers why people will choose it every day.**

---

## Purpose

Vestara exists to help people understand, improve, and build software by combining structured cognition with governed engineering.

Before Vestara writes code, it understands.
Before it changes systems, it explains.
Before it automates work, it earns trust.

Every capability should reinforce that purpose.

---

## The Product Principles

### 1. Understand Before Acting

```
Open → Understand → Explain → Plan → Ask → Execute → Verify → Remember
```

Understanding is the prerequisite for every action.

### 2. The CLI Is the Canonical Experience

Every capability exists first as a command. The Workspace, IDE, desktop shell, mobile application, and future operating system are different interfaces to the same runtime — not separate implementations. One cognitive engine. Many experiences.

### 3. Four Brains, One Experience

Users never interact with individual cognitive systems. They interact with Vestara. Internally Conversation communicates, Memory remembers, Knowledge understands, Executive decides. Externally: Vestara helps me accomplish my work. The architecture remains invisible.

### 4. Capabilities Over Features

A feature adds functionality. A capability changes what the user is able to accomplish. Every sprint should deliver a capability.

### 5. Trust Before Automation

Automation is valuable only when users understand why it happened. Every recommendation should be explainable. Every execution should be traceable. Every autonomous action should have a reason.

---

## The North Star Metric

> **How quickly can Vestara transform an unfamiliar software project into a comprehensible one?**

If a developer opens a repository they've never seen before and, within minutes, understands what it is, how it works, where to start, what the risks are, and what should happen next, then Vestara has delivered real value.

Everything else — the Four Brains, the runtime, the contracts, the architecture — is in service of that outcome.
